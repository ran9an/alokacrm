# n8n orchestration
Import workflows/intake.json, configure BOTH header-auth credentials, and set CRM_API_URL to the API private address. Workflow is intentionally inactive. Set the CRM credential header to Authorization: Bearer <INTAKE_TOKEN>. Source webhook needs its own unrelated secret.

Every source adapter must produce the canonical intake envelope documented in docs/api.md. Website forms go through a server adapter; never embed INTAKE_TOKEN in a browser. Portal adapters depend on the available vendor API/email feed and are not fabricated here. Click-to-WhatsApp is an inbound conversation, not a Meta instant-form webhook. Capture referral metadata where supplied; otherwise source is unknown/manual until mapped with evidence. Verify vendor signatures at each adapter before calling canonical intake.

Schedule workflow: call GET /v1/automation/export using AUTOMATION_TOKEN, then upsert rows by lead UUID into Master and filtered source/owner tabs using Google Sheets nodes. Use one serialized export execution, never append blindly. No reverse sync. The sheetsSnapshot TypeScript adapter is an alternative snapshot writer; rows left over after shrink must be cleared by the orchestration workflow. Export endpoint currently returns the full register; paginate before very large deployments.

Follow-up orchestration: schedule approved nurture steps by POST /v1/automation/followups using AUTOMATION_TOKEN, with leadId in the body. Do not call OpenWA directly from n8n. The worker is the sole outbound dispatcher. Nurture cadence should stop on reply pending human review; the supplied webhook pauses on replies and handles explicit STOP. All inbound replies pause nurture automatically; resume tooling is a rollout task.

Existing OpenWA webhook -> authenticated adapter -> normalized POST /v1/webhooks/openwa. The supplied CRM endpoint accepts a normalized envelope, not every native OpenWA version's payload. Inspect your VPS API explorer and configure the mapping before enabling messaging. Never replace/redeploy the existing OpenWA service as part of this stack.

GA4 and Meta functions are supplied adapters, not enabled event subscriptions. Before wiring integration_jobs to conversion delivery, add explicit analytics/marketing consent and GA client ID to intake/schema, map approved conversion events, validate GA4 with its debug endpoint, and use Meta test events. Never send customer names or phone numbers to GA4. Use the same Meta event_id in browser/server events for deduplication. Jobs retain retry metadata; an integration dispatcher is a planned extension, not running in the messaging worker.
