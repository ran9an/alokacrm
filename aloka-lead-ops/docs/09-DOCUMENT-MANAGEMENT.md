# Document management

## Current state

Migration `003_operational_crm.sql` provides document metadata: lead, kind, access class, object key, original filename, verification state, uploader and timestamps. No binary is stored in PostgreSQL.

Actual upload, signed download and verification APIs are **not implemented**. KYC file handling must remain disabled until the controls below exist.

## Required implementation

- Private S3-compatible bucket; no public object ACLs.
- Server-authorized signed upload and short-lived signed download URLs.
- Object keys generated by the server and scoped to the lead.
- File size, content-type and malware checks.
- Role and ownership checks on every operation.
- Immutable versions rather than overwriting documents.
- Audit events for upload, download of sensitive files, verification and rejection.

## Access classes

- `INTERNAL`: brochures and project-public material.
- `SENSITIVE`: internal supporting documents.
- `HIGHLY_SENSITIVE`: PAN, Aadhaar and executed deeds.

Do not enable KYC collection merely because metadata tables exist.
